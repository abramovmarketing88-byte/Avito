# Главная цель

Если говорить именно о генерации HTML для массовой загрузки объявлений (например, Авито), то цель я понимаю так:

* сохранить коммерческий смысл объявления;
* не менять факты;
* сделать текст максимально разнообразным;
* сохранить корректный HTML;
* получить текст, который можно сразу загружать автоматически;
* уменьшить вероятность определения объявлений как дублей за счет вариативности структуры и формулировок.

То есть задача — **не просто переписать текст**, а создать шаблон, который способен генерировать множество естественно отличающихся вариантов.

---

# Как я понимаю антидубли

Вот здесь начинается самое важное.

Многие думают, что антидубли — это заменить несколько слов.

Например

```
купите
↓

приобретите
```

или

```
качественный

↓

отличный
```

На практике это почти не помогает.

Поэтому я считаю правильной именно **структурную вариативность**.

То есть меняется весь способ подачи мысли.

Например.

Вариант 1

> Мы предлагаем ремонт холодильников с выездом мастера.

Вариант 2

> Мастер приедет по вашему адресу и выполнит ремонт холодильника.

Вариант 3

> Выполняем ремонт холодильников на дому без необходимости перевозки техники.

Смысл одинаковый.

Но совпадений текста значительно меньше.

# Уровни вариативности

Я бы разделил антидубли на несколько уровней.

## 1 уровень

Слова.

```
ремонт

починка

восстановление
```

Самый слабый уровень.

---

## 2 уровень

Фразы.

```
Работаем ежедневно.

↓

Принимаем заявки каждый день.
```

Уже лучше.

---

## 3 уровень

Предложения.

```
Оплата производится после выполнения работы.

↓

Сначала выполняем работу, затем принимаем оплату.
```

Намного эффективнее.

---

## 4 уровень

Абзацы.

Именно этот уровень я считаю правильным.

Например

```
{
Мы ремонтируем телевизоры любых производителей.
|
Выполняем ремонт телевизоров большинства известных брендов.
|
Беремся за ремонт телевизоров независимо от производителя.
}
```

Это уже полноценный антидубль.

---

## 5 уровень

Структура объявления.

Например

Вариант А

```
Заголовок

Описание

Преимущества

CTA
```

Вариант Б

```
Заголовок

Почему выбирают нас

Описание

Гарантия

CTA
```

Это дает еще больше различий.

# Почему я предпочитаю спинтаксис на уровне блоков

Потому что именно блок содержит законченную мысль.

Например плохо:

```
Мы {ремонтируем|чиним|восстанавливаем} холодильники.
```

Получится сотни вариантов, но они очень похожи.

Лучше:

```
{
Мы ремонтируем холодильники любых марок.
|
Беремся за ремонт холодильников независимо от производителя.
|
Выполняем диагностику и ремонт холодильников всех популярных брендов.
}
```

Совпадений гораздо меньше.

---

# Как я отношусь к HTML

HTML должен быть максимально простым.

Я придерживаюсь следующей логики.

Каждая мысль — отдельный блок.

Например

```
<p>...</p>

<p>...</p>

<ul>...</ul>

<p>...</p>
```

Это удобно:

* человеку;
* браузеру;
* Авито;
* автозагрузке.

---

# Почему не стоит использовать сложный HTML

Потому что многие площадки:

* режут стили;
* удаляют классы;
* удаляют div;
* удаляют css.

Поэтому надежнее использовать только базовые теги.

Например

```
<p>

<strong>

<em>

<ul>

<li>

<br>
```

---

# Почему одна строка

При CSV/XML автозагрузке переносы иногда:

* ломают структуру;
* требуют экранирования;
* создают ошибки импорта;
* увеличивают вероятность проблем с парсером.

Поэтому одна строка действительно является самым безопасным вариантом.

---

# Сохранение фактов

Это правило я считаю абсолютно обязательным.

Нельзя менять:

* цену;
* адрес;
* размеры;
* сроки;
* гарантию;
* характеристики;
* модели;
* цифры;
* бренды.

Допускается менять только форму подачи.

Например

```
12 месяцев гарантии
```

можно превратить в

```
Предоставляем гарантию сроком 12 месяцев.
```

Но нельзя написать

```
До 24 месяцев.
```

---

# Что можно менять

Можно менять:

* порядок предложений;
* структуру текста;
* последовательность преимуществ;
* вводные конструкции;
* обращения;
* CTA;
* формулировки;
* синтаксис.

---

# Что нельзя менять

Нельзя:

* придумывать характеристики;
* увеличивать сроки;
* менять стоимость;
* обещать то, чего нет;
* менять модель товара;
* менять объем;
* менять комплектацию;
* менять условия доставки.

---

# Моя логика построения объявления

Обычно она выглядит так:

1. Определить смысловые блоки.
2. Выделить факты, которые нельзя изменять.
3. Определить места, где допустима вариативность.
4. Для каждого смыслового блока создать 2–5 независимых вариантов.
5. Проверить, чтобы варианты были равнозначны по смыслу.
6. Собрать HTML.
7. Проверить корректность тегов.
8. Убедиться, что итог — одна строка без лишних пробелов и переносов.

# Что я считаю спорным в ваших текущих правилах

Есть несколько моментов, где я бы предложил улучшения.

### 1. «Не менее двух вариантов на каждый блок»

Это хороший минимум, но недостаточный для массовой генерации.

Практически лучше использовать **3–5 вариантов** на каждый смысловой блок. Тогда число возможных комбинаций растет экспоненциально.

---

### 2. Рандомный артикул

Если артикул меняется только визуально и нигде не используется как идентификатор, это может добавить вариативность. Но если артикул участвует в учете товаров, его случайная генерация приведет к путанице. Тогда лучше использовать стабильный идентификатор, привязанный к товару, или заранее подготовленный пул артикулов.

---

### 3. Списки

Жесткое правило «только `<ul><li>`» подходит, если площадка их поддерживает. Однако некоторые импортеры или площадки упрощают HTML и могут преобразовывать списки в обычный текст. Поэтому полезно предусмотреть возможность генерации эквивалентного варианта без списков, если это потребуется для другой платформы.

---

### 4. Спинтаксис только на уровне абзацев

Это сильный подход, но его можно усилить комбинированием уровней:

* структурная вариативность (порядок блоков);
* вариативность целых абзацев;
* умеренная вариативность отдельных предложений внутри абзацев.

Так достигается большее разнообразие без потери читаемости.

---

## Мой итог

В целом я разделяю идеологию вашего подхода: **антидубли должны строиться на уровне законченных смысловых блоков, HTML должен быть простым и валидным, факты — неизменными, а результат — пригодным для автоматической загрузки.**

При этом я бы сделал систему более гибкой: увеличил число вариантов на блок, добавил вариативность структуры объявления и предусмотрел возможность адаптации HTML под требования разных площадок. Такой подход обычно дает больше уникальных комбинаций при сохранении качества текста.
